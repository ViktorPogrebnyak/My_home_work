# Исправление SmartShop для домашнего задания № 6

Исходники серверного приложения в этом репозитории отсутствуют. `static/index.js`
взят из учебного JAR и дополнен сохранением корзины в `localStorage`.
При загрузке восстанавливаются товары, количество и сумма. Изменение количества,
удаление товара и успешное оформление заказа также сохраняют актуальное состояние.
Повреждённые данные хранилища не препятствуют запуску страницы.

## Запуск

В PowerShell из корня проекта, с настроенным `JAVA_HOME`:

```powershell
./smartshop/start.ps1
```

Скрипт запускает приложение на http://localhost:8080 с отдельной базой в памяти.
Перед запуском остановите другой экземпляр учебного приложения на порту 8080.
После остановки сервера данные этой базы исчезают. Исходный JAR и файловая база
`data/smartshop.mv.db` не изменяются. Для другого расположения JAR или порта:

```powershell
./smartshop/start.ps1 -JarPath 'C:/path/to/application.jar' -Port 8080
```

Во втором терминале установите `API_USERNAME`, `API_PASSWORD`,
`UI_ADMIN_USERNAME`, `UI_ADMIN_PASSWORD` согласно настройкам учебного приложения.
Перед контрольным прогоном запустите новый экземпляр `start.ps1`, чтобы база
в памяти была чистой. Затем выполните:

```powershell
$env:API_BASE_URL = 'http://localhost:8080'
./gradlew.bat uiTest --rerun-tasks
```

В IntelliJ IDEA конфигурация `uiTest` также должна использовать
`API_BASE_URL=http://localhost:8080`. Это и адрес по умолчанию в `UiApiSupport`.
Команда Gradle в этой конфигурации: `uiTest --rerun-tasks`, чтобы каждый запуск
выполнял тесты заново, даже если код не менялся.

Отчёт: `build/reports/tests/uiTest/index.html`.
Прямой запуск исходного JAR без `start.ps1` не подключает исправленный JavaScript.

Контрольный прогон 22.10.2026 в IntelliJ IDEA на исправленном приложении
`http://localhost:8080`: **13 тестов, 0 падений**, `BUILD SUCCESSFUL in 16s`
(Selenium — 4, Selenide — 5, сценарии вебинара — 4). Также проверены сумма
корзины после обновления и отсутствие оформленных товаров после повторной загрузки.

## Исходное учебное приложение

ДЗ требует проверять тот же учебный JAR, который использовался в ДЗ № 5.
В исходном приложении корзина хранится в переменной JavaScript `let cart = []`
и обнуляется при обновлении страницы. Тесты 1.4 и 2.4 проверяют требуемое сохранение
и должны выявлять этот дефект. Исправление из этой папки — отдельная доработка
приложения: успешный прогон на ней не подтверждает исправность исходного JAR.

Повторная проверка 22.10.2026: исходный JAR — **11/13**, два падения только
в сценариях сохранения корзины; приложение с исправлением — **13/13**.
Пропущенных тестов нет. Раздельные отчёты:

- исходный JAR: `build/hw6-check/original/uiTest/index.html`;
- приложение с исправленной корзиной: `build/hw6-check/patched/uiTest/index.html`.

### Ограничение удаления через API

При дополнительных прогонах подтверждена причина ошибки `500` при очистке:
в `ProductController.delete()` учебного JAR явно задан ответ `500` для ID 50–53.
Это постоянная ошибка для этих ID, поэтому повтор DELETE её не устраняет.
Тесты не принимают `500` за успешную очистку и не пропускают упавшие проверки.
При многократных запусках на одной базе автоинкремент достигает этого диапазона.
Для воспроизводимого контрольного прогона используйте свежий сервер с базой
в памяти из `start.ps1`. Исправление JavaScript не меняет серверный контроллер.

Формат сдачи в условии — публичный репозиторий и ссылка на коммит.
Для сдачи используйте коммит с этими исправлениями:
старый коммит `de11a51` содержит первоначальный вариант тестов.
